> **Owning service:** Pricing & Offer Service (MA-101), `services/pricing-offer` (FastAPI on Fargate, no datastore in its current build). No new service, no database.

## 2. Problem Statement

`POST /pricing/quote` applies one flat tax rate (`PRICING_DEFAULT_TAX_RATE_PERCENT`, 5%) to every product, and returns only cart-level totals. That's wrong in two ways that block a GST invoice:

1. **Wrong tax.** Fresh milk is nil-rated (0%), yet the flat rate charges 5% on it. Catalog already stores each product's `hsnCode` and `taxRate` (MA-156, editable in the admin portal, MA-157), and Pricing already fetches each product from Catalog per quote. It just reads only `price`.
2. **No breakdown.** An invoice needs, per line: HSN, unit price, taxable value, rate, and CGST/SGST or IGST amounts. It also needs the delivery fee as its own taxed line. None of that is returned today, so Order (MA-159) cannot store it.

**Expected outcome:**
- Each quote taxes every product at its own Catalog rate.
- Tax is split correctly between CGST+SGST (intra-state) and IGST (inter-state).
- The response carries a per-line breakdown in integer paise that sums exactly to the amount charged.
- Every existing response field keeps its meaning, so the mobile app and Order Service keep working unchanged.

## 3. Scope

### In Scope

- Read `hsnCode`, `taxRate` and `name` from Catalog's existing `GET /products/{id}` response; today the client reads only `price`.
- Per-line tax computation in integer paise, split by supply type.
- Delivery fee as a taxed service line (SAC code and rate from configuration; the fee amount is GST-inclusive, see FR-4).
- New response fields `lines`, `deliveryFeeLine`, `supplyType`, `placeOfSupplyState`, `netPayablePaise`. Existing fields are unchanged.
- A missing-tax-data guard behind a configuration flag.
- Seed `hsn_code`/`tax_rate` for every local-dev product in `services/local-dev/_catalog_seed_data.py`.
- README update: the "Scope" section's flat-rate and no-split bullets are removed.

### Out of Scope

- **Offers and discounts engine** (MA-101 full build / MA-45). `discountPaise` is always 0 per line until offers exist; the field exists so the invoice's Disc % column has a source.
- **Cess.** No dairy product attracts compensation cess; the invoice prints 0.
- **A `CatalogUpdated` read model or Redis cache** (MA-122's full design). Synchronous Catalog lookups remain.
- **Changes to the mobile `Quote` model.** New fields are additive and ignored by the app.
- **Real GST rate values.** Finance supplies them through the admin portal; seed values are local-dev placeholders.

## 4. Functional Requirements

### FR-1: Per-product rate and HSN

- For each requested item, Pricing reads `price`, `name`, `hsnCode` and `taxRate` from the Catalog product it already fetches.
- The line's tax rate is the product's `taxRate` (a percentage, e.g. `0`, `5`, `12`, `18`).
- If `hsnCode` or `taxRate` is null:
  - **When `PRICING_REQUIRE_TAX_DATA=true`** (default in every non-local environment), the quote fails with **422 `PRODUCT_TAX_DATA_MISSING`**, `details: {productId}`.
  - **When `false`** (local-dev default), the line falls back to `PRICING_DEFAULT_TAX_RATE_PERCENT` and `hsnCode: null`, and a warning is logged with `productId`.

### FR-2: Supply type

- `supplyType` is `INTRA_STATE` when the request's `deliveryState` equals `PRICING_SELLER_STATE`, otherwise `INTER_STATE`. The comparison is case-insensitive with surrounding whitespace trimmed.
- `placeOfSupplyState` in the response is `deliveryState` as sent (trimmed).
- `PRICING_SELLER_STATE` is required configuration. Start-up fails without it in non-local environments.

### FR-3: Product line computation (tax-exclusive prices)

Catalog `price` is the **pre-tax** unit price. This matches today's behaviour (`netPayable = basePrice + taxAmount + deliveryFee`) and the Order Details mock (Item Total + Delivery Fee + Taxes & Fees = Grand Total). For each line:

| Field | Rule |
|---|---|
| `unitPricePaise` | `round_half_up(price × 100)` |
| `discountPaise` | `0` (no offers engine) |
| `taxablePaise` | `unitPricePaise × quantity − discountPaise` |
| `taxPaise` | `round_half_up(taxablePaise × taxRate / 100)` |
| `cgstPaise`, `sgstPaise` | `INTRA_STATE` only: `cgstPaise = taxPaise // 2`, `sgstPaise = taxPaise − cgstPaise` (the odd paisa goes to SGST) |
| `igstPaise` | `INTER_STATE` only: `taxPaise` |
| `totalPaise` | `taxablePaise + taxPaise` |

Unused split fields are `0`, never null.

### FR-4: Delivery fee line (GST-inclusive)

The configured `PRICING_DELIVERY_FEE` (₹20 today) remains the amount the customer pays; its GST is **inside** that amount, not added on top, so no customer is charged more than today.

| Field | Rule |
|---|---|
| `sacCode` | `PRICING_DELIVERY_FEE_SAC` (default `996813`) |
| `taxRatePercent` | `PRICING_DELIVERY_FEE_TAX_RATE_PERCENT` (default `18`) |
| `grossPaise` | `round_half_up(PRICING_DELIVERY_FEE × 100)` |
| `taxablePaise` | `round_half_up(grossPaise × 100 / (100 + rate))` |
| `taxPaise` | `grossPaise − taxablePaise` |
| CGST/SGST/IGST | Split as in FR-3 |

For example: gross 2000 at 18% gives taxable 1695 and tax 305 (intra-state: CGST 152, SGST 153).

### FR-5: Aggregates (existing fields, unchanged meaning)

| Field | Rule |
|---|---|
| `basePrice` | Σ `taxablePaise` / 100 |
| `taxAmount` | Σ product-line `taxPaise` / 100 (**excludes** the fee's internal tax, which is already inside `deliveryFee`) |
| `deliveryFee` | `grossPaise` / 100 |
| `netPayable` | `netPayablePaise` / 100 |
| `taxRate` | Effective rate: `round(taxAmount / basePrice × 100, 2)`, or `0` when `basePrice` is 0. **Behaviour change:** no longer a constant 5. |

- `netPayablePaise` = Σ product-line `totalPaise` + `deliveryFeeLine.grossPaise`.
- `monthlyEstimate` is unchanged (`netPayable × occurrences`).

**Invariant (must hold for every response):** `netPayablePaise == Σ lines[].totalPaise + deliveryFeeLine.grossPaise` and `netPayable × 100 == netPayablePaise`.

### FR-6: Response contract (additive)

```json
{
  "basePrice": 113.0, "taxAmount": 2.25, "taxRate": 1.99, "deliveryFee": 20.0,
  "netPayable": 135.25, "monthlyEstimate": null, "discountAmount": null, "appliedOfferId": null,
  "netPayablePaise": 13525,
  "supplyType": "INTRA_STATE",
  "placeOfSupplyState": "Karnataka",
  "lines": [
    { "productId": "cow-milk", "productName": "Cow Milk", "hsnCode": "0401", "quantity": 1,
      "unitPricePaise": 6800, "discountPaise": 0, "taxablePaise": 6800, "taxRatePercent": 0.0,
      "cgstPaise": 0, "sgstPaise": 0, "igstPaise": 0, "totalPaise": 6800 },
    { "productId": "set-curd", "productName": "Fresh Curd", "hsnCode": "0403", "quantity": 1,
      "unitPricePaise": 4500, "discountPaise": 0, "taxablePaise": 4500, "taxRatePercent": 5.0,
      "cgstPaise": 112, "sgstPaise": 113, "igstPaise": 0, "totalPaise": 4725 }

  "deliveryFeeLine": { "sacCode": "996813", "grossPaise": 2000, "taxablePaise": 1695,
```

`lines[]` preserves the request's item order.

## 5. Non-Functional Requirements

- **Correctness:** all money maths uses integers (paise) and `Decimal` for ratio steps, with ROUND_HALF_UP. No float arithmetic before the final `/100` presentation.
- **Performance:** no new network calls; Catalog fan-out is unchanged. Added CPU is negligible.
- **Backward compatibility:** every existing field keeps its name, type and meaning, except `taxRate`, which becomes the effective rate (FR-5). The mobile app reads `taxRate` only for display.
- **Observability:** log `supplyType`, line count and `netPayablePaise` with the correlation ID. Add the metric `pricing.tax_data_missing.count` (tagged by product) for FR-1.
- **Security:** unchanged (internal service; no PII in the request).

## 6. Technical Design

### Architecture Approach

- **Catalog client:** `CatalogClientPort.get_price` becomes `get_product`, returning a `CatalogProduct(price, name, hsn_code, tax_rate)` dataclass. Same endpoint, retry and error mapping.
- **Tax maths:** a pure `domain/tax.py` module with `split(tax_paise, supply_type)`, `exclusive_line(...)` and `inclusive_line(...)`. All functions are deterministic and unit-testable.
- **Wiring:** `PricingService.quote` builds `QuoteLine`s and a `FeeLine`, then derives the aggregates from them. The flat-rate path survives only as the FR-1 fallback.

### Component Responsibilities

| Component | Change |
|---|---|
| `adapters/catalog_client.py` | Parse `name`, `hsnCode`, `taxRate` in addition to `price` |
| `domain/models.py` | Add `SupplyType`, `QuoteLine`, `FeeLine`; extend `Quote` |
| `domain/tax.py` (new) | Paise rounding and CGST/SGST/IGST split |
| `domain/pricing_service.py` | Per-line computation; aggregates derived from lines |
| `domain/exceptions.py` | `ProductTaxDataMissingError` → 422 |
| `handlers/dto.py` | Serialize the new fields |
| `config/env.py` | `seller_state`, `require_tax_data`, `delivery_fee_sac`, `delivery_fee_tax_rate_percent` |

### API / Interface Definitions

- `POST /pricing/quote`: the request is unchanged; the response is per FR-6.
- New error: `422 PRODUCT_TAX_DATA_MISSING`, `details.productId`.

### Configuration

| Var | Default (local) | Notes |
|---|---|---|
| `PRICING_SELLER_STATE` | `Karnataka` | Required outside local; must equal Invoice's seller GST state (MA-160) |
| `PRICING_REQUIRE_TAX_DATA` | `false` | `true` outside local |
| `PRICING_DELIVERY_FEE_SAC` | `996813` | Finance to confirm |
| `PRICING_DELIVERY_FEE_TAX_RATE_PERCENT` | `18.0` | Finance to confirm |

### Data Flow

Request → validate → fetch Catalog products concurrently → compute lines → compute the fee line → derive aggregates → assert the invariant → respond.

## 7. Data Considerations

- No schema; Pricing has no database.
- **Seed data:** `_catalog_seed_data.py` gains `hsn_code`/`tax_rate` for every product. These are local-dev placeholders, and finance confirms production values:

| Category | HSN | Placeholder rate |
|---|---|---|
| Fresh milk | `0401` | 0 |
| Curd / yogurt | `0403` | 5 |
| Paneer | `0406` | 5 |
| Ghee | `0405` | 5 |
| Fresh vegetables | `0701`–`0714` per item | 0 |

- **Validation:** `taxRate` must lie in 0–28, else it is treated as missing (FR-1).

## 8. Integration Considerations

- **Upstream:** Catalog `GET /products/{id}`, unchanged and already called.
- **Downstream:**
  - **Order Service** (MA-159) consumes `lines`, `deliveryFeeLine`, `supplyType`, `placeOfSupplyState` and `netPayablePaise`. Until MA-159 ships, Order ignores them.
  - **Mobile `Quote.fromJson`** ignores unknown keys.
- **Failure behaviour:** unchanged for Catalog outages (existing retries, then 503). Only FR-1's 422 is new.

## 9. Edge Cases and Failure Modes

| Case | Behaviour |
|---|---|
| All items 0% (milk only) | `taxAmount` 0, `taxRate` 0, lines have all split fields 0 |
| `basePrice` 0 (a future 100% discount) | `taxRate` 0; no division by zero |
| Odd tax paise, intra-state | CGST gets the floor and SGST the remainder |
| `deliveryState` differs only in case or whitespace | Treated as intra-state |
| Product with null tax data, flag on | 422; the whole quote fails (no partial quote) |
| `taxRate` outside 0–28 | Treated as missing |
| Delivery fee configured as 0 | Fee line has all-zero amounts; still present |

## 10. Testing Strategy

- **Unit (`domain/tax.py`):**
  - Rounding at .5 paise boundaries.
  - Odd-paisa split.
  - The inclusive fee back-calculation (2000 at 18% → 1695 + 305).
  - A 0% rate.
  - An IGST path.
- **Unit (`PricingService`):**
  - A mixed cart with 0% and 5% items: lines, aggregates and the invariant.
  - Intra- vs inter-state.
  - Flag on → `ProductTaxDataMissingError`; flag off → fallback plus warning.
  - Effective `taxRate`.
  - `monthlyEstimate` unchanged for a subscription item.
- **Contract:** a serialized response contains every existing key with its old type plus the new keys; snapshot-test against FR-6's example.
- **Negative:** Catalog returning `taxRate: null`, `taxRate: 40`, or `hsnCode: ""`.
- **Regression:** the existing pricing test suite passes after updating the expected `taxRate` values.

## 11. Risks and Trade-offs

- **Price drop on 0% items.** Milk quotes drop by 5% versus today. This is correct for GST, but it's a visible price change; Product and Finance should know before release.
- **Inclusive delivery fee.** This keeps customer charges unchanged, at the cost of Milkful absorbing the fee's GST. The alternative, adding 18% on top (₹23.60), is a one-line configuration change if Finance prefers it (see §12).
- **`taxRate` semantics change** (constant → effective rate). It is only displayed in the app today; any consumer treating it as "the rate" would show a blended figure.
- **Synchronous Catalog dependency for tax data.** This is unchanged from today; MA-122's read-model design stays the long-term option.
