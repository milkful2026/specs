## 2. Problem Statement

MA-34 makes the cart the place where a customer reviews and confirms both one-time
items and subscriptions. Cart Service today can't support that:

- A subscription line has no **delivery slot**, but Subscription Service's create
  contract requires `slotId` (MA-131 FR-1). The slot is chosen on the product screen and
  currently lost if the line goes into the cart.
- `GET /cart` returns one aggregated quote. For a mixed cart the review screen must show
  what is **charged now** (one-time lines) separately from what each **subscription
  delivery** costs (charged later by the Daily Run).
- Order Service (MA-136) must read the user's cart and remove the checked-out lines
  server-side; both operations are JWT-only today.
- The review screen must show the **full delivery address**. The customer entered it on
  the Google Maps / Places address screen at onboarding (MA-1), and User Service stores
  it in full (`lines`, `landmark`, `city`, `state`, `pincode`, `lat`, `lng`), but
  `GET /users/me` only returns the default address's ID, state and zone.

Expected outcome: cart lines carry everything checkout needs, the review screen gets an
accurate split and the full delivery address, and Order Service can read/clear a cart
over an internal route.

## 3. Scope

### In scope

- Optional `slotId` on line items: required for subscription frequencies, forbidden for
  `ONE_TIME` — on `POST /cart/items`, `PUT /cart`, and in every line serialization.
- `GET /cart` gains `payNowQuote` and `perDeliveryQuote`; existing `quote` unchanged.
- `GET /cart/internal/users/{userId}` — internal read (same body as `GET /cart`, minus quotes).
- `POST /cart/internal/users/{userId}/remove-items` — internal, version-checked removal
  of a set of line IDs.
- `CartUpdated` event emitted for the internal removal, same as any other mutation.
- User Service: `GET /users/me` returns the full default address (FR-6).

### Out of scope

- Any change to Pricing & Offer Service.
- Storing prices in the cart (quotes stay live).
- Slot validation against Inventory at add time beyond what exists — Subscription
  Service validates the slot at checkout.
- Wallet gate rules (unchanged).

## 4. Functional Requirements

### FR-1: `slotId` on line items

- `AddItemRequestDto` and `ReplaceCartItemDto` gain `slotId: str | None`.
- Validation in `CartService` (alongside the existing `startDate` rule at
  `cart_service.py:163-165`):
  - `frequency.is_subscription` and `slotId` missing/blank → `400 VALIDATION_ERROR`,
    message `"slotId is required for a subscription item"`.
  - `frequency == ONE_TIME` and `slotId` present → `400 VALIDATION_ERROR`,
    message `"slotId must not be set for a ONE_TIME item"`.
- `LineItem` gains `slot_id: str | None`; `serialize_line_item` emits `"slotId"`.
- Stored lines written before this change have no `slotId`; they deserialize as `None`
  and stay readable. MA-136 rejects them at checkout (`LINE_INVALID`).

### FR-2: Split quote on `GET /cart`

`GET /cart` response `data` becomes:

```json
{
  "items": [ /* line items incl. slotId */ ],
  "cartVersion": 7,
  "quote":            { /* unchanged: all lines, existing behavior */ },
  "payNowQuote":      { /* ONE_TIME lines only, or null */ },
  "perDeliveryQuote": { /* subscription lines only, or null */ }
}
```

- `payNowQuote`: Pricing quote for the `ONE_TIME` lines only. `null` if there are none.
- `perDeliveryQuote`: Pricing quote for the subscription lines only, each sent with its
  own frequency, representing **one delivery of every subscription line**. `null` if
  none. Its `monthlyEstimate` is populated by Pricing only when all subscription lines
  share one frequency (existing Pricing behavior); otherwise `null`.
- `quote` keeps its current meaning so existing callers (MA-123 app build) don't break.
- Pricing rejects an empty `items` list, so a sub-quote with zero lines is never requested
  (`null` instead).
- Pricing calls for the three quotes run concurrently; if any one fails, `GET /cart`
  fails exactly as it does today when its single quote fails (no partial quote set).

### FR-3: Internal read — `GET /cart/internal/users/{userId}`

- Returns `{items, cartVersion}` (the `serialize_cart` shape), no quote — Order Service
  prices on its own at checkout.
- Empty/missing cart → `200` with `items: []`, `cartVersion: 0`.

### FR-4: Internal remove — `POST /cart/internal/users/{userId}/remove-items`

Request:

```json
{ "itemIds": ["li_1", "li_2"], "ifVersion": 7, "reason": "CHECKOUT", "checkoutId": "chk_..." }
```

- Removes exactly the listed lines in one `transact_write_items` transaction, together
  with an outbox row and the `META` `cartVersion` increment (same pattern as
  `delete_item`).
- `ifVersion` ≠ current `cartVersion` → `409 CART_VERSION_CONFLICT`, nothing removed.
  **Exception (idempotent replay):** if none of the listed IDs exist any more and the
  current version is higher than `ifVersion`, return `200` with the current cart. This is
  how a retried checkout is recognized as already cleared.
- Some IDs present, some absent, at the right version → remove the present ones, `200`.
- Response: `{items, cartVersion}` after removal.
- The `CartUpdated` outbox payload carries `reason: "CHECKOUT"` and `checkoutId`.

### FR-5: Internal route protection

- Both internal routes are served under API Gateway with **IAM (SigV4) auth**, same as
  User Service's internal address-state route that Order Service already signs for
  (`order/src/adapters/user_client_adapter.py`). Only Order Service's task role gets
  `execute-api:Invoke` on them.
- The `userId` path parameter is trusted **only** on these IAM-protected routes; public
  routes keep deriving it from JWT claims.

### FR-6: User Service — full default address on `GET /users/me`

- `GET /users/me` adds `defaultAddress`, `null` when the user has no default address:

```json
"defaultAddress": {
  "id": "addr_…",
  "lines": ["Flat 402, Sai Heights", "Baner Road"],
  "landmark": "Near Baner Gaon bus stop",
  "city": "Pune",
  "state": "Maharashtra",
  "pincode": "411045",
  "lat": 18.559,
  "lng": 73.786
}
```

- Values are exactly what the onboarding Google Maps / Places screen saved (MA-1 /
  MA-93 FR-1); nothing is re-geocoded. `landmark` may be `null`.
- The existing flat fields `defaultAddressId`, `defaultAddressState`,
  `defaultAddressZoneId` stay unchanged for existing app builds.
- `UserRepository.get_profile_by_sub` already loads the default address row
  (`user_repository.py:167-190`); it exposes the whole row as `UserProfile.default_address`
  instead of copying only `state`/`zone_id`. No extra query.
- `serialize_user_profile` emits `defaultAddress` via a new `serialize_address` helper.

## 5. Non-Functional Requirements

- **Latency:** `GET /cart` p95 ≤ 600 ms with three concurrent Pricing calls (today:
  one call). Internal routes p95 ≤ 200 ms.
- **Consistency:** the internal remove is atomic with the version bump and outbox row.
- **Security:** internal routes unreachable with a Cognito JWT alone; no `userId` from a
  client body on public routes.
- **Observability:** log `cart.internal.remove_items` with `userId`, `checkoutId`,
  `removedCount`, `cartVersion`; existing request-id propagation.
- **Compatibility:** no field removed or renamed; `quote` unchanged.

## 6. Technical Design

- `domain/models.py`: `LineItem.slot_id`; `CartView` gains `pay_now_quote`,
  `per_delivery_quote`.
- `domain/cart_service.py`:
  - slot validation next to the existing startDate rule;
  - `get_cart` partitions lines by `frequency.is_subscription` and requests up to three
    quotes concurrently (`ThreadPoolExecutor`, as the handler is sync Lambda);
  - `get_cart_internal(user_id)`, `remove_items_internal(user_id, item_ids, if_version,
    checkout_id)`.
- New handlers `internal_get_cart_handler.py`, `internal_remove_items_handler.py`, wired
  in `composition.py`; routes + IAM authorizer in `infra/cart/cart_stack.py`.
- DynamoDB item attribute `slotId` (string, optional) — no table/index change.

## 7. Data Considerations

- New optional attribute `slotId` on `LINE#` items. No migration; absence = `None`.
- `CartUpdated` event schema (`shared/events`): add optional `reason`
  (`"CUSTOMER" | "CHECKOUT"`, default `"CUSTOMER"`) and optional `checkoutId`.

## 8. Integration Considerations

| Counterparty | Contract | Failure behavior |
|--------------|----------|------------------|
| Pricing & Offer | Existing `POST /pricing/quote`, called for each non-empty partition | Any failure → `GET /cart` fails as today (`503`) |
| Order Service (MA-136) | Caller of FR-3/FR-4 via SigV4 | Order Service retries 5xx; treats `409` as `CART_CHANGED` |
| Mobile (MA-137) | Sends `slotId` on subscription adds; reads the split quotes | Old app builds ignore new fields |

## 9. Edge Cases and Failure Modes

| Case | Behavior |
|------|----------|
| Legacy subscription line without `slotId` | Readable; shown normally; rejected at checkout by MA-136 with `LINE_INVALID` |
| `PUT /cart` from an old app build omitting `slotId` on a subscription line | `400` — acceptable: the old build can't check out anyway |
| Cart has only one-time lines | `perDeliveryQuote: null` |
| Cart has only subscription lines | `payNowQuote: null` |
| Remove retried after success | Replay rule in FR-4 → `200`, nothing removed twice |
| User with no default address | `defaultAddress: null`; MA-137 hides the address and MA-136 rejects checkout with `DELIVERY_ADDRESS_UNKNOWN` |
| Customer edits cart between checkout read and remove | `409` → MA-136 surfaces `CART_CHANGED` (only possible if the customer edits from a second device mid-checkout) |

## 10. Testing Strategy

- **Unit:** slot validation matrix (subscription ± slot, one-time ± slot); partitioning
  (one-time only, subscription only, mixed, empty); remove-items version match, mismatch,
  replay-after-success, partial-present.
- **Integration (moto DynamoDB, stubbed Pricing):** `GET /cart` issues exactly one
  Pricing call per non-empty partition + one for `quote`; internal remove writes lines,
  outbox and version in one transaction; `CartUpdated` payload has `reason: CHECKOUT`.
- **Contract:** `GET /cart` response validated against the updated OpenAPI; old fields
  byte-identical for a one-time-only cart.
- **Negative:** internal routes return `403` with a Cognito JWT and no SigV4.
- **User Service (FR-6):** `GET /users/me` with a default address returns every stored
  field in `defaultAddress`, with `landmark: null` when unset; with no default address,
  `defaultAddress: null`; the three flat fields are unchanged in both cases.

## 11. Risks and Trade-offs

- Three Pricing calls per `GET /cart` instead of one; accepted for correctness of the
  split. Alternative (Pricing returning per-partition totals in one call) is cleaner but
  changes a Done service's contract — revisit if latency targets are missed.
- Keeping `quote` alongside the split quotes is redundant, but it avoids breaking
  installed app builds.

## 12. Open Questions

- Should `ONE_TIME` lines also carry a (delivery) `slotId` later? Out of scope now
  (PO-5); the field design allows it by relaxing the FR-1 rule.
