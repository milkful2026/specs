## 2. Problem Statement

My Orders (MA-145) needs a place customers can reach it from. The `my_profile` mock puts a
**My Orders** row on the Profile screen, but the app has no Profile screen: the **Profile**
tab on the Home, Schedule and Wallet bottom bars is a stub that does nothing when tapped.
Expected outcome: the Profile tab opens a minimal Profile screen, following the mock's layout,
that links to My Orders and to the existing screens behind the mock's other working rows.

## 3. Scope

### In scope

- Route `/profile` with a minimal Profile screen:
  - a header with the customer's name and mobile number;
  - rows for **My Subscription**, **My Orders** and **Transactions**.
- The **Profile** tab wired on the three existing bottom bars (Home, Schedule, Wallet).
- The Profile screen's own bottom bar, with Profile selected.

### Out of scope

- Rows in the mock with no backend or feature yet: **Refer & Earn** (MA-30), **Offer Zone**
  (MA-29), **Account & Preferences**.
- The mock's profile edit button, avatar photo, "VIP" badge and "Freshoza VIP Member" pill.
- Moving Logout (it stays where it is today, on Home).
- Redesigning the bottom bar: it stays **Home / Schedule / Wallet / Profile**, which already
  matches the `my_profile` mock.

## 4. Functional Requirements

### Screen structure

```
AppBar (no back arrow — it's a tab):  Profile
┌ Header card ─────────────────────────┐
│ (initials avatar)  Name              │
│                    +91 98765 43210   │
└──────────────────────────────────────┘
┌ My Subscription            Manage > ┐  (green hero row, as in the mock)
┌ (box)  My Orders                  > ┐
FINANCIALS
┌ (receipt)  Transactions           > ┐
Bottom bar: Home | Schedule | Wallet | [Profile]
```

### FR-1: Route and navigation model

- `GoRoute('/profile')` → `ProfileScreen`.
- It is a **tab destination**, like `/subscriptions` and `/wallet`: bottom-bar taps use
  `context.go('/profile')`, not `push`, so there is no back arrow.

### FR-2: Wire the Profile tab on existing bottom bars

On each of the three existing bottom bars — `_HomeBottomNav` (`home_screen.dart`),
`_SubscriptionsBottomNav` (`subscriptions_screen.dart`) and the Wallet screen's bar
(`wallet_screen.dart`) — tapping index 3 (**Profile**) calls `context.go('/profile')`. The
"Profile remains a stub" comments are removed. The other indices keep their current
behaviour.

### FR-3: Profile screen's bottom bar

The same four items, with `currentIndex: 3`:
- Home → `context.go('/home')`
- Schedule → `context.go('/subscriptions')`
- Wallet → `context.go('/wallet')`
- tapping Profile does nothing

### FR-4: Header card

- Loads `ProfileRepository.getMe()` on open.
- Shows the **name** (`UserProfile.name`), and the **mobile number** formatted `+91 98765
  43210` when it's a 10-digit Indian number with or without `+91`; otherwise as stored.
- **Avatar:** a circle with the name's initials (up to 2 letters) on the primary-tint colour.
  No photo, and no edit button.
- **Loading:** name and number placeholders.
- **Error:** the header shows **"Couldn't load your profile"** with a **"Retry"** text
  button. **The rows below always render and work**, because they don't depend on the
  profile.

### FR-5: Rows

| Row | Visible label | Icon | Action |
|-----|---------------|------|--------|
| Hero row | **My Subscription** + a pill **"Manage"** with `>` | subscriptions/repeat icon | `context.go('/subscriptions')` |
| Row | **My Orders** | box / inventory icon | `context.push('/orders')` (MA-145) |
| Section label | **FINANCIALS** | — | — |
| Row | **Transactions** | receipt icon | `context.push('/wallet/transactions')` (the existing route; MA-27 builds its content) |

- Each row is a full-width card, at least 56dp tall, and tappable anywhere with a ripple.
- There are no count badges (no order counts; that would mean an extra call for no mock
  requirement).

## 5. Non-Functional Requirements

| Area | Target |
|------|--------|
| Performance | Rows render immediately; only the header waits for `getMe()` |
| Accessibility | Row semantics = visible label + "button"; 48dp+ targets; header announced as "{name}, {mobile}"; AA contrast |
| Consistency | Uses `app_theme.dart` colour and typography tokens; no hard-coded hex values |
| Maintainability | The bottom-bar wiring is identical on all four screens. Extracting a shared `AppBottomNav` widget is **allowed but not required** here (if done, it must keep each screen's existing behaviour and tests) |

## 6. Technical Design

| File | Change |
|------|--------|
| `lib/features/profile/presentation/profile_screen.dart` (new) | Screen, header, rows, bottom bar |
| `lib/features/profile/bloc/profile_header_cubit.dart` (new) | `ProfileHeaderCubit(ProfileRepository)`: `load()`; states `loading / loaded(UserProfile) / error` |
| `lib/core/router/app_router.dart` | Adds `GoRoute('/profile')`, which provides the cubit |
| `home_screen.dart`, `subscriptions_screen.dart`, `wallet_screen.dart` | Bottom-bar index 3 → `context.go('/profile')` |

`ProfileRepository` is already provided in `main.dart`, so no new dependency is needed.

## 7. Data Considerations

Read-only use of `UserProfile` (`name`, `mobile`). Nothing is stored or written.

## 8. Integration Considerations

| Dependency | Contract | Failure behaviour |
|------------|----------|-------------------|
| User Service `GET /users/me` (existing `ProfileRepository.getMe`) | `UserProfile` | Header error + Retry; rows still work |
| `/orders` (MA-145), `/subscriptions`, `/wallet/transactions` | Existing routes | If MA-145 isn't merged yet, the My Orders row is built but the route must exist for navigation. Implement MA-145 first, or in the same PR |

## 9. Edge Cases and Failure Modes

| Case | Behaviour |
|------|-----------|
| Name empty | Header shows "Milkful customer"; the initials avatar shows a person icon |
| Mobile missing or unusual format | Shown as stored; hidden if empty |
| `getMe()` fails | Header error + Retry; the rows work |
| Profile tab tapped while already on Profile | No-op |
| Android back on Profile | Same as the other tab roots (the app's existing behaviour for `/subscriptions` and `/wallet`) |

## 10. Testing Strategy

**Cubit:** loaded; error; retry → loaded.

**Widget (`find.text`):**
- **Scenario: Profile renders.**
  - Given `getMe` returns "Alex Thompson" / "9876543210".
  - Expect "Profile", "Alex Thompson", "+91 98765 43210", "My Subscription", "Manage",
    "My Orders", "FINANCIALS" and "Transactions".
  - Expect **no** "Refer & Earn", "Offer Zone" or "Account & Preferences".
- **Scenario: rows navigate** (GoRouter harness):
  - "My Orders" → `/orders`;
  - "Transactions" → `/wallet/transactions`;
  - "My Subscription" → `/subscriptions`.
- **Scenario: header failure doesn't block rows.** `getMe` throws → "Couldn't load your
  profile" + "Retry", and tapping "My Orders" still navigates.
- **Scenario: Profile tab wired.** On the Home, Subscriptions and Wallet screens, tapping
  the "Profile" bottom-bar item navigates to `/profile`. Update each screen's existing
  widget test that currently expects the stub.
- **Scenario: Profile's own bar.** Profile is selected; tapping "Home", "Schedule" or
  "Wallet" navigates to `/home`, `/subscriptions` and `/wallet`.
- **Keys:** `Key('profile.header')`, `Key('profile.row.orders')`,
  `Key('profile.row.subscription')`, `Key('profile.row.transactions')`.

**Integration:** Home → Profile tab → My Orders → back → Profile.

## 11. Risks and Trade-offs

- **Minimal vs mock:** Profile ships with three of the mock's rows. Each later story (MA-27,
  MA-29, MA-30, account settings) adds its own row, so there are no dead links in the
  meantime.
- **Bottom bars duplicated on four screens:** the wiring must stay consistent. A shared
  widget would remove the duplication, but it touches three existing features; it's left
  optional here.
- **Transactions goes to a placeholder** until MA-27. This is accepted: the route already
  exists and Wallet links to it today.
