## 2. Problem Statement

The Order Details screen already has a **Bill Details** card, but it shows only **Grand Total**. Order Service stored no breakdown (MA-146 §3), and no invoice existed anywhere. MA-159 now returns a per-order `bill`, and MA-160 issues a downloadable GST invoice each day after delivery.

The customer should see how the total was built up (Item Total, Delivery Fee, Taxes & Fees, Grand Total, as in the mock) and should be able to download the invoice PDF and save or share it.

## 3. Scope

### In Scope

- `OrderBill` model parsed from the optional `bill` on `OrderSummary`.
- **Bill Details** card: Item Total, Delivery Fee and Taxes & Fees rows above the existing Grand Total row, shown only when `bill` is present.
- **Download Invoice** row with every state, placed after the **Payment Method** card and before **Reorder Items** / **Support**.
- `InvoiceRepository`, `InvoiceInfo` and `InvoiceCubit`.
- Download to a temporary file and open the system share sheet (iOS and Android). On web, open the URL in a new tab.
- New packages: `path_provider`, `share_plus`.
- `AppConfig.invoiceBaseUrl`, following the existing per-service pattern (`--dart-define=INVOICE_BASE_URL`, local default port 8010).

### Out of Scope

- Rendering the PDF in-app (the share sheet's preview or "Open in" covers viewing).
- The per-line tax table in the app (it's on the PDF).
- Invoice lists or history screens.
- Any change to My Orders list rows.

## 4. Functional Requirements

### FR-1: Model

- `OrderSummary` gains `final OrderBill? bill;`, parsed from `json['bill']` (`null` when absent or null).
- `OrderBill` has `itemTotalPaise`, `deliveryFeePaise`, `taxPaise`, `grandTotalPaise` (ints).
- The per-line `lines` array in the response is ignored by this spec.

### FR-2: Bill Details card

| Condition | Rows (top to bottom) |
|---|---|
| `bill != null` | **Item Total** `formatPaise(itemTotalPaise)`; **Delivery Fee** `formatPaise(deliveryFeePaise)`; **Taxes & Fees** `formatPaise(taxPaise)`; divider; **Grand Total** (existing `BillRow`, unchanged: struck-through and caption logic as today) |
| `bill == null` | Exactly today's card: **Grand Total** only, including the `—` for `amountPaise == 0` |

- All amounts use `formatPaise(…, alwaysDecimals: true)`, e.g. "₹130.00".
- Grand Total keeps reading `order.amountPaise` (which equals `bill.grandTotalPaise`).
- If the components don't add up to `amountPaise` (a backend contract violation), the card falls back to Grand Total only and logs a debug warning. The screen never displays inconsistent numbers.

### FR-3: Download Invoice visibility

The row is shown only when `order.status == CONFIRMED && order.bill != null`. It is hidden for every other status (CREATED, PAYMENT_FAILED, FAILED, NEEDS_ATTENTION, CANCELLED) and for orders without a bill.

### FR-4: Download Invoice states

`InvoiceCubit` is created by the screen when FR-3 holds, and calls `check(orderId)` once on load and on pull-to-refresh.

| State | UI |
|---|---|
| `InvoiceChecking` | Row label **"Download Invoice"**; trailing 20dp `CircularProgressIndicator`; row disabled |
| `InvoiceNotReady` (404 `INVOICE_NOT_READY` or `INVOICE_NOT_FOUND`) | Label **"Download Invoice"**; subtitle **"Invoice available after delivery"**; trailing download icon greyed; row disabled |
| `InvoiceReady(info)` | Label **"Download Invoice"**; trailing `Icons.download`; enabled |
| `InvoiceDownloading` | As Checking; row disabled |
| `InvoiceCheckFailed` (network or 5xx on check) | Label **"Download Invoice"**; subtitle **"Couldn't check invoice. Tap to retry."**; enabled; a tap re-runs `check` |

**Tap flow (from `InvoiceReady`):**

1. Emit `InvoiceDownloading`.
2. Call `GET /orders/{orderId}/invoice` **again** for a fresh `downloadUrl`; never reuse a possibly expired one.
3. Download the bytes with a **separate `Dio` instance without the auth interceptor**. A pre-signed S3 URL must not receive the Cognito `Authorization` header, or S3 rejects it.
4. Write the file to `getTemporaryDirectory()/Milkful-Invoice-<invoiceNo with "/" → "-">.pdf`.
5. Open the share sheet with `share_plus` (`XFile(path, mimeType: 'application/pdf')`), subject **"Milkful invoice <invoiceNo>"**.
6. Emit `InvoiceReady(info)` again.

**On any failure in steps 2–5:**
- SnackBar **"Couldn't download invoice. Try again."**
- Return to `InvoiceReady`.
- If step 2 now returns 404, go to `InvoiceNotReady` instead.

**On web** (`kIsWeb`): replace steps 3–5 with `launchUrl(downloadUrl, webOnlyWindowName: '_blank')` (existing `url_launcher`).

### FR-5: Keys and semantics

| Element | Key | Semantics |
|---|---|---|
| Item Total row | `Key('orderDetail.bill.itemTotal')` | label "Item Total, ₹113.00" |
| Delivery Fee row | `Key('orderDetail.bill.deliveryFee')` | label "Delivery Fee, ₹20.00" |
| Taxes & Fees row | `Key('orderDetail.bill.taxes')` | label "Taxes and Fees, ₹2.25" |
| Download row | `Key('orderDetail.downloadInvoice')` | `button: true`; label "Download invoice PDF"; `enabled` mirrors state |

These follow the existing `orderDetail.*` key convention (`orderDetail.reorder`, `orderDetail.support`).

## 5. Non-Functional Requirements

- **Accessibility:**
  - Row touch target ≥ 48dp.
  - The spinner has a semantics label "Checking invoice" / "Downloading invoice".
  - Disabled states are announced as dimmed.
  - Text contrast follows the existing `DetailCard` styles.
- **Performance:**
  - The invoice check is a single GET that does not block the rest of the screen (the row renders in `InvoiceChecking`).
  - A typical PDF is under 100 KB.
- **Privacy:**
  - The PDF is written only to the app's temporary directory; the OS clears it.
  - No invoice data is cached in `shared_preferences`.
- **Offline:** the check fails, so the row shows `InvoiceCheckFailed` and the rest of the screen behaves as today.

### API contract used

- `GET /orders/{orderId}` → `bill: {itemTotalPaise, deliveryFeePaise, taxPaise, grandTotalPaise, lines[]} | null`
- `GET /orders/{orderId}/invoice` → 200 `{invoiceId, invoiceNo, issuedOn, invoiceValuePaise, downloadUrl, urlExpiresAt}` | 404 `INVOICE_NOT_FOUND` | 404 `INVOICE_NOT_READY`

## 7. Data Considerations

- No local persistence.
- `OrderBill` is nullable everywhere. Old cached `OrderSummary` JSON (if any) parses to `bill: null`.

## 8. Integration Considerations

- **MA-159 must ship before** the Bill Details breakdown appears; until then `bill` is absent and the screen is unchanged.
- **MA-160 must ship before** Download Invoice becomes useful. Until then the check returns 404 (or a connection error locally, if Invoice isn't running), so the row shows **"Invoice available after delivery"** or the retry state. It never crashes.
- The pre-signed URL host is S3, not the API host. The no-auth download client prevents leaking the Cognito token to S3.

## 9. Edge Cases and Failure Modes

| Case | Behaviour |
|---|---|
| Old order, no `bill` | Grand Total only; no Download row (AC-9) |
| CONFIRMED, today's delivery, before 11:00 IST | "Invoice available after delivery" |
| Order cancelled while the screen is open, then refresh | Download row disappears (FR-3) |
| URL expired between check and tap | The tap always re-fetches (FR-4 step 2) |
| Share sheet dismissed without action | Nothing to do; state returns to Ready |
| Double tap | The second tap is ignored (the row is disabled while Downloading) |
| Bill components don't sum | Fallback to Grand Total only (FR-2) |
| No network on tap | SnackBar "Couldn't download invoice. Try again." |

## 10. Testing Strategy

**Unit:**
- `OrderSummary.fromJson` with `bill`, with `bill: null`, and without the key.
- `InvoiceInfo.fromJson`.
- `InvoiceRepository` maps each 404 code to `null` and throws on other errors.
- `InvoiceCubit` (`bloc_test`): check → Ready / NotReady / CheckFailed; tap → Downloading → Ready; a tap with a 404 on re-fetch → NotReady; a tap with a download error → SnackBar event plus Ready.

**Widget:**
- **Scenario: bill breakdown.**
  - **Given:** a CONFIRMED order with `bill {11300, 2000, 225, 13525}`.
  - **Expect:** text "Item Total" with "₹113.00", "Delivery Fee" with "₹20.00", "Taxes & Fees" with "₹2.25", and "Grand Total" with "₹135.25", found by `Key('orderDetail.bill.itemTotal')` and its siblings.
- **Scenario: legacy order.**
  - **Given:** `bill: null`.
  - **Expect:** "Grand Total" present; no "Item Total"; no `Key('orderDetail.downloadInvoice')`.
- **Scenario: invoice not ready.**
  - **Given:** the repository returns null.
  - **Expect:** "Download Invoice" and "Invoice available after delivery"; tapping does nothing.
- **Scenario: invoice ready, tap.**
  - **Given:** a fake repository and a fake share service.
  - **Steps:** tap `Key('orderDetail.downloadInvoice')`.
  - **Expect:** a spinner, then share invoked with a file whose name ends with `.pdf`.
- **Scenario: hidden for cancelled.** A CANCELLED order with a bill shows no Download row.
- **Scenario: download error.** The fake repository throws on download; expect the SnackBar text "Couldn't download invoice. Try again.".

**Integration (`integration_test`, local-dev stack):**
- Open a confirmed order created after MA-159, run `run_invoices_local.py`, pull to refresh, tap **Download Invoice**, and assert the share sheet opens (Android emulator).

**Accessibility:**
- `meetsGuideline(androidTapTargetGuideline)` and `labeledTapTargetGuideline` on the screen.

## 11. Risks and Trade-offs

- **Share sheet instead of an in-app viewer.** No PDF-viewer dependency, and it works the same on both platforms. The trade-off is one extra tap to "Save to Files".
- **One extra GET per detail view** (the invoice check). It's cheap, and avoids adding a cross-service `invoice` field to Order's response.
- **Another per-service base URL.** This matches how every other service is configured today. Builds that point at API Gateway set `INVOICE_BASE_URL` to the same host as Order.
